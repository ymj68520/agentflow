## Migration policy

1. A legacy five-field snapshot can supply exact A **source values**. This is
   not conversion into frozen model@5 full pin and not recovered construction.
2. A successor request can pair those values with an actual current Context
   and actually execute C. Valid means a fresh current observation. If all Some
   slots are Valid and all other admission conditions hold, it can satisfy
   successor Subject admission; the current implementation still cannot do so.
3. Without current relation module/import closure, keep Missing/incomplete.
   No global lookup/None replacement. Incompatibility yields actual C Invalid,
   not changing old Raw verdict. Retrying with a **different explicit input
   Context** is a new observation, never mutation of the old Subject.
4. A construction-sensitive request for an old snapshot without an authentic
   retained receipt is **not migratable**. Attaching a new edition label,
   checking current schema, matching bytes/revision or hashing the family does
   not create that receipt. C cannot satisfy a B requirement.
5. Old native equality stays unchanged forever in its old contract. A/B empty
   source values remain equal; source equality is not validation observation
   equality across contexts. A future B-based equality would require actual
   extra inputs and a separately versioned contract, not retroactive correction.
6. Cross-edition direct decoding, unknown draft variants and structural
   lookalike owners fail closed. Registration success is not support/activation;
   unsupported portable/current-only routes continue to deny capabilities.

## Independent Python Oracle design — not a Full-field implementation

Future Oracle input must be a complete independent fixture package: exact
source snapshot components/slot, full canonical native catalog value and bytes,
complete supplied Context module/universe inputs, actual occurrence binding,
exact compiler sources, optional actual expected comparison pin. Rust Actual
is NEVER a source for Expected, mutation fixtures or case applicability.

Four separately derived Expected products are mandatory:

1. **Native Snapshot Source Expected**: independently construct the full
   per-kind T value from fixture inputs, apply the frozen per-kind canonical
   row ordering, derive complete ACE1 catalog bytes and plain SHA256, compare
   to the fixture's claimed source fields. Preserve every field/variant, option
   and empty collection. Family and revision are source values, not schema pins.
2. **Schema Source/Binding Expected**: parse/compile the actual supplied AFIDL
   sources with independent Python code; check unique exact identities, missing
   imports/cycles and selected closed slot family/root; derive the complete
   canonical TypeSchema and its full HashV1 digest. An old native source has
   construction_history=Unavailable; never choose A/B by observing Rust output.
3. **Current Context Validation Expected**: independently implement the DRAFT
   staged lookup/canonical catalog/encode/decode/full round-trip checks, exact
   revision comparison applicability and typed failure payloads. Distinguish
   NotReached, Missing, malformed ambiguous inputs, mismatches, Found, Invalid
   and Valid. Do not fake native ambiguity; it is a wire/admission boundary.
   No current schema means no concrete schema_ref. No lookup of global defaults.
4. **Complete Typed Relation Snapshot Expected**: assemble exact A source and
   independently derived C observation with the proposed successor's real
   registered nominal descriptors and full typed input references. Verify full
   Context/Subject/reference closure and admission separately from Raw events.
   Until that successor is registered and implemented this product cannot be
   emitted as a current formal Fact. A design string or Rust serde JSON is not
   a registered complete typed value.

Compare recursively by exact token/type/owner, full map/set uniqueness and
ordering, all field keys and full payloads, complete digest algorithms/domains,
full definition closure, source association, witness graph links and all
required output relations. Do not compare only expected keys or hash/count
summaries. Mutation design must include every omitted/replaced field and
cross-link, wrong owner/root/domain/digest/checksum, swapped Some slots, None
for Some, source/context substitution, cycle, wrong stage and spurious Valid.
These are future Comparator duties, not a new set of executed mutations here.

The unchanged independent diagnostic Oracle already compiles A/B and computes
their actual full schema ACE1/digests from source. Its input-derived output is

later; do not copy Rust branch outputs or turn its nine diagnostic omissions
