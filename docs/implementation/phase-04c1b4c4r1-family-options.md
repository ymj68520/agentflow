**PROPOSED — NOT REGISTERED.** No new family/case/edition is registered here.

| Option | Semantic fit/completeness | Cost/risk | Decision |
| --- | --- | --- | --- |
| A: extend contract_validation family within existing Scope | Investigated first. There is no such existing Family. B's completeness argument: [subject](phase-04c1b4c4r1-operand-and-context-identity.md) supplies each original operand/context; [roster](phase-04c1b4c4r1-twelve-dimension-roster.md) covers every returned dimension and all local relations; [draft](phase-04c1b4c4r1-normative-amendment-draft.md) distinguishes gate/shortcut/relation/fold/copy, defines closed statuses/witnesses and requires complete branches. No property depends on a nonexistent root object. Existing root/control/leaf/prerequisite family meanings remain unchanged. This is a subject/coverage argument, not a minimal-edit preference.

Reusing contract_validation storage as an internal representation is allowed in a later implementation only if its full logical projection still matches the selected standalone profile. It does not avoid registering the new logical branch or change the recommendation into Option A. No implementation/storage layout is chosen by this design.
