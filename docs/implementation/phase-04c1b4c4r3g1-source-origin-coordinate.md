# IR-free native occurrence identity — DRAFT,NOT REGISTERED

Unit of native source is the complete canonical ComponentContract declaration under its actual native context binding,not an invocation or a root call. Contract lineage is only catalog/name;declaration identity retains every canonical field and exact bytes. No Checked-only ComponentContractDigest is demanded from a negative canonical diagnostic. Exact compiler/context inputs belong to future Scope;T3's safe local borrowed binding remains PendingG02.

Proposed NativeGuardOccurrence={action_binding_ordinal:u64,action_identity:RecoveryActionIdentity,effect_row_kind:closed|open_known|unknown,forward:NativeResolution<EffectOccurrence>,action:NativeResolution<EffectOccurrence>,usage:NativeResolution<UsageOccurrence>}. NativeResolution is the closed sum not_queried|absent|present(payload),not an unknown/default index. EffectOccurrence={ordinal:u64,entry:EffectEntry};UsageOccurrence={ordinal:u64,binding:RecoveryUsageBinding}. The action binding itself always exists for an emitted per-binding row. Its ordinal is recovered from the validated canonical action vector with full-identity uniqueness,not from a counter or result push order.

Canonicalization sorts full action keys and rejects duplicates. E ordinals address exactly the selected Closed vector or Open.known vector;Unknown has no entry. They are not raw pre-canonical array indices or binding ordinals. Raw/canonical validation provenance retains its actual association;never assert that a canonical ordinal was the original raw position. Standalone direct use of a noncanonical raw native API is not automatically admitted as a validated G01 diagnostic.

It identifies actual declaration members and variant selection. Origin:predicate plus the actual canonical declaration root path.recovery_action_bindings[i];guard-input applications additionally use the REAL binding.identity.forward_effect or .action_effect reference field,while coordinate retains the resolved E-entry guard definition. This is an application at a declared reference,not a fictional guard literal inside RecoveryActionIdentity. Subject/context origins use their actual admitted input root and context association query. Distinct cases/guard roles/bindings are distinct applications. AssertionPath is known empty for the native non-root profile. No caller/node is present.

Content-identical canonical declaration+context scope+same binding application is one formal native origin even when evaluated twice. Distinct invocation times or Rust object addresses are not extra origins. Different native declarations (complete content/context) or different binding occurrences/roles remain distinct despite equal guard text. If an external format later needs byte-identical separately declared units,it must supply a formally declared container/path;this design does not mint a runtime identity for those units. Root call-sites are separately declared ROOT occurrences and add observations/consumer joins,not native source copies.
