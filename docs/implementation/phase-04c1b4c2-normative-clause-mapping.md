## Exact replacement/addition text for approval

A1 (D01/D10): "Copies of one FactKey SHALL have identical role, evaluation, status, requirement, prerequisites, references, primary, contradiction and auxiliary evidence status. Only observation-site sets may differ and are unioned. A conflict SHALL return InvalidFacts."

A2 (D02/D04): "A context/compiler source SHALL carry a validated scope-relative typed member path; the enclosing exact Scope supplies its content. It SHALL NOT contain Scope, Fact, Obligation or final report as a descendant. An invalid assertion claim SHALL remain an explicitly typed raw-byte comparison operand."

A3 (D03/D08): "The registered predicate roster SHALL define kind/clause/class, role, status domain, applicability and mandatory dependencies. Conditional unknown is a missing premise; unsupported fallback dimensions SHALL NOT acquire meaning from legacy text."

A4 (D12): "The descriptor table is a registered non-wire semantic model. Its exact bytes and semantics edition, not AFIDL numbers or host reflection, bind canonical field/tag/order meanings. Existing complete AFIDL model values reuse exact source-pinned descriptors; all additional descriptors SHALL be closed."

A5 (D13/D14), **availability-changing refinement**: Replace "This restates ... existing ... conditions" by "Five-plus-nine restates proof eligibility only. In this edition, CompleteAndValid fact capture AND successful bounded normalization/encoding are additional capability-creation preconditions. Normalization failure SHALL return a distinct error with no CheckedRootExportCompatibility. It SHALL NOT change proof verdicts, add a body-evidence premise, or authorize a caller-provided report."

A6 (D14): "Incomplete normalization produces no valid projected eligibility claim. A typed failure is not a report with EligibleStatic=false, and does not erase a separately observed proof result. There is no public unchecked constructor or fallback old-edition constructor in the current-only build."

A7 (D15/D16): "Only the implementation-owned successor tuple is supported. Legacy verification executes the pinned old implementation, not a dispatcher added to the new compiler. New-edition Expected is independently derived in a new namespace. No future full-field pass is claimed until G02 and applicable G03 evidence closes."

These amendments settle the draft's registration ambiguities without changing Option A, substantive Effect/Recovery/Control algebras, verdict priority, F03/F04 or runtime boundaries.
