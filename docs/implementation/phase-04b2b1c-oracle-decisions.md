# Phase 4B.2B.1C — Oracle and Fixture Decisions

Baseline: `dc497a6ec70d535ca0a31803f25e5a10feec2fc0`. Corpus revision: **3 → 4**. CaseIds and count are unchanged (**58**). Revision 3 remains recoverable from the baseline commit. The Python generator remains an independent oracle; it does not import or invoke Rust.

Revision 4 records these input/oracle corrections:

1. **`proof/missing-usage-not-zero`: invalid control opcode.** The input used `operator: "compose"`, which is not a Semantic IR opcode. It is now an actual SEQUENCE over the same unresolved and known Usage contributions. The Expected remains unknown rather than finite zero. This changes only the invalid test input encoding and makes the planned ControlDerivation stage executable.
2. **Checked-child omissions were ambiguous.** Earlier generator defaults simultaneously labelled a child `checked_component` and encoded omitted Effect/Failure/Usage/Flow as null. The production fixture adapter consequently treated that child as an unresolved exact component pin. Revision 4 gives a checked leaf explicit empty Effect, Failure, Usage, and Flow values when those dimensions are intended to be known-empty. An explicitly unresolved child remains null and still carries no positive claim. Expected is regenerated from those explicit test inputs, not read by the fixture builder.
3. **Effect resource ports are explicitly mapped.** For known Effect entries, the fixture now declares the resource alias needed to construct a valid checked IR mapping. The alias is compared in the per-child Resource projection; the builder no longer silently invents a caller resource slot while Expected says no resource mapping exists.
4. **Recovery identity/coverage is now fully specified.** `race/loser-recovery-retained` supplies exact forward and action EffectAtoms, action kind, every Recovery clause field (idempotency, key requirement, reconciliation, compensation, unknown-effect handling), activation/attempt bounds, per-attempt Recovery Usage, the complete-meter set, and a sufficient Recovery ceiling. The fixture constructs a real `RecoveryContract`, exact action bindings, exact recovery-Usage bindings, and a coverage snapshot from those declared inputs; the production checker validates the snapshot and both contestants' actions are compared.
5. **Invalid Flow source aliases were replaced by typed ports.** `input:a`/`input:b` are not valid `WorkflowInput(u32)` identities; they are now `input:1`/`input:2`. The unordered-members fixture uses the same valid typed source members in opposite orders.
6. **`proof/authority-upper-not-permission` no longer requests an unavailable external-origin proof.** Its source facts are statically typed workflow inputs with different declared authority ceilings. The test remains about a may-carry upper bound not becoming an effective authority/grant. Unknown external influence remains covered by the dedicated RequiresEvidence/proof vectors; the fixture does not claim a checked ComponentContract can prove an unknown external origin.
7. **Presentation metadata equivalence follows its stated semantics.** Revision 3's generator compared the full objects, so labels `before`/`after` yielded `violation`, contradicting the vector note that presentation metadata does not change semantic control facts. Revision 4 removes only the presentation `label` before semantic normalization and freezes `proven`; the production side confirms identical checked IR/contract digest and control projection.
8. **Typed merge compares the real rejection stage.** The old abstract expected output described a merge result despite the frozen typed-output rule requiring rejection. Revision 4 freezes `IrValidation`, `parallel_output_type_mismatch`, and AF-SEMANTIC-0056. The builder uses distinct resolved schema types and the actual `SemanticIrDocument::check` API.
9. **The cross-sibling Sequence vector now contains a real edge.** Its producer declares a typed output, the consumer expression reads the producer value slot, Phase 3C analyzes the dataflow, and the production dependency projection is asserted. The independent Expected now marks Flow transfer Unproven and identifies producer/consumer nodes, value slot, and expression.
10. **Unsupported TIMEOUT Expected preserves known facts.** The unknown-control result now includes the known child Effect contribution, ensuring unknown propagation cannot pass by dropping all available information.
11. **Unknown-child Effect subtotals use operator-specific lower-bound rules.** The independent oracle now weakens known contributions for later SEQUENCE children, all RACE/FAIL_FAST children, and dynamic SELECT branches before returning an incomplete parent row. This corrects the previous oracle behavior that returned the unadjusted child lower bound when any sibling was unresolved.

These are test-input/oracle corrections within the existing corpus revision mechanism. No unrelated CaseId was added or removed; no frozen ABI or digest surface was changed. The before/after corpus diff and repeat-generator checks are recorded in the gate report.
