## Eight stage questions, answered separately

1. Current T3 has sealed local source/event borrows; no implemented canonical
   structural Node carrier for this complete Raw Subject. No native address,
   local index or metadata `dag_ref` shape success is an admitted DagRank source.
2. No existing registered implemented pre-capture stage supplies that carrier.
   G02/T4 are pending. Mathematical constraints in 0217 are not implementation
   availability or permission for T3 to allocate new ranks.
3. For a genuinely pre-existing exact canonical graph, verified ranks may be read
   only after complete typed content/root/environment validation. The actual R4
   native/Compiler inputs do not provide such a graph. The proposed binder must
   construct and verify one later, after explicit registration/implementation.
4. Proposed canonical input-rank authority belongs solely to the registered
   Structural Input Binding stage. It never assigns ObligationIdentity, FactKey
   normalization IDs or arbitrary per-event numbers. This G1 task assigns none.
5. Existing Native T3 local references/PendingScope are legitimate local evidence
   under NG-LINKS; they are not the full registered Raw carrier required here.
6. Such a borrowed view does not satisfy Node<T>/DagRank. The user reaffirmed
   that distinction in C2R4; this design preserves it, not weakens it.
7. A pipeline that requires T4's Fact-derived complete Scope to build inputs for
   those same Facts is cyclic. Merely scheduling a placeholder T4 pass earlier
   or filling ranks backward does not solve it.
8. Recommend a separately approved pre-capture stage owning structural input
   canonicalization. Keep semantic Fact/obligation normalization and full G02
   transport/integration separate. No current predicate Stage enum is changed.

## New stage contract and source-to-Fact scheduling

The proposed binder consumes only complete declared input data and verified
in-process source/owner/Context associations. It validates shapes/Raw byte
preservation, resolves the closed structural-site table, validates complete
reference closure/sets/maps, and constructs/verifies a canonical minimal immutable
input graph G. It returns G with exact tuple, registered profile/root roster,
typed input-reference environment and a nonportable lifetime-bound association
receipt. The receipt is not a graph input, source identity, Fact or capability.

Raw branch events may already have been captured by the unchanged native hook;
they are source-preserved observations outside G. The binder must neither demand
their complete Fact/Obligation output nor evaluate port correctness to create
input identity. Bad port zero is legal Raw input data, not a binding failure.

After structural binding, the actual C algorithm operates on that same native
Context and A values; C outputs reference source/Context nodes in G. Complete Raw
Subject admission additionally requires all actual Some slots C Valid and the
existing real source/compiler/Context associations. Only then may complete Raw
Fact assembly consume sealed genuine port events and the verified input ranks.
No Fact is emitted on C Missing/Invalid. Actual port verdict/prefix is unchanged.

**Required successor clarification:** current OS@6 prose says Some without C
Valid blocks full Subject materialization. To bind a single stable input graph
before C, explicitly distinguish *structurally typed candidate Subject data node*
from *admitted Subject usable as a Fact source*. Candidate input data may exist
in G; the admission result is outside G and is required for all Fact consumers.
This is a formal successor amendment, not an interpretation silently applied to
model@6. If registration declines it, Option B is not implemented and no Raw
resumption is admitted. C-Missing keeps only diagnostics/candidate inputs and
real port evidence, never an admitted subject or14 fake Fact fields.

T4 later validates complete semantic facts, consistency/support/consumers,
obligation derivation, typed minimums, identity and report encoding. It consumes
the immutable G; it cannot append nodes/roots or alter G's ranks. If additional
real input evidence is required, the input roster was incomplete: fail closed,
rebind a new complete carrier from actual inputs and perform fresh admissions
and capture. Do not patch existing references with a relocation dictionary.

G02 retains complete lossless Scope, remote reconstruction/association and
cross-process integration responsibility. The binder takes the explicitly
registered input-graph construction dependency out of the formerly ambiguous
T3/T4/G02 boundary; it does not claim to finish all of G02 or authorize any T4
implementation here. Fresh remote association cannot authenticate old native
pointers. T5/T6/T7/T8 and all other producers remain separate prerequisites.
