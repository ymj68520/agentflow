# 候选比较与裁决

| 方案 | 可重复/跨进程 | 独立同内容来源 | 安全边界 | 裁决 |
|---|---|---|---|---|
| A：复用现有精确绑定 | 现有内容身份可重复 | Raw闭包没有Owner/O；Application等不同域不可挪用 | 会改写旧Source语义 | 审查完成，未找到 |
| B：指针/分配号/临时执行ID | 进程变化即丢失；重放不稳定 | 只能区分临时对象，不代表正式来源 | 伪造Origin/观察即来源 | 拒绝作为Portable方案 |
| C：受检显式声明域/Owner/真实容器slot | 完整包和键相同可独立重算 | 可以；同时保存完整内容 | DeclaredOnly，不建立外部认证 | 唯一推荐 |
| D：仅document digest/关闭DAG去重 | digest仍使相同内容相等；改rank破坏规范 | 不能或破坏现有身份合同 | hash-only/随机salt/冗余节点绕行 | 拒绝 |

C的必要前提不是“调用者说两个地址不同”，而是实际提交的有限封闭来源包。
若没有这种输入，C明确拒绝；不能为追求可用性退回B。外部认证是另一权限边界，
不能借此扩大本设计；独立持久系统handle尚未有封闭adapter则UnsupportedOwnerVariant。

Owner命名是声明域内的名字，不是全球权威。为每次调用临时编造包/键不满足
来源先于验证的要求；调用者显式新提交一个真实来源包可以建立新的声明性身份，
但不能声称这是旧输入当年的历史来源，也不能据此获得任何新证明权限。
