## Phase 4C.1B admission and exit conditions

This report defines conditions, **not authorization to begin 4C.1B**.
The user must separately authorize that implementation phase.

Before implementation:

1. Preserve these data meanings and C01–C07. Resolve mechanical materialization
   collisions/AFIDL compiler constraints without inventing missing semantics;
   a meaning change needs an explicit design revision.
2. Register additive versioned closed shapes and all proposed number bindings.
   Compute actual canonical TypeSchemaDigests only then. Existing 16 modules,
   477 assignments, 14 domains and every old golden remain immutable; any new
   counts are reported separately as authorized additive work.
3. Define the exact post-registration compiler manifest/support entry. Whole
   registry content changes identity even when checker source does not. Do not
   overwrite an old proof's labels or claim historical dispatch exists.
4. Design lossless enumeration for all private universe members and exact raw
   Option/association projection before any deduplicating/overwriting constructor.
5. Use no external origin approval as a substitute for content validation.
   Pure static reconstruction needs no origin authority, while publication
   remains separately blocked.

Implementation closure requires **all**, not a partially working happy path:

1. Registered schemas, closed production Decoder, typed content inverse paths
   and exact per-scope reconstruction, including numeric/Unicode/graph limits.
2. Fresh formal contract/IR/dataflow/resolver/joint Root/RootRecovery/checker
   execution, with semantic-canonical byte/pin equality and new local capabilities.
3. Both codec laws and reconstructed expanded-projection equality demonstrated
   by independent cross-language implementations, typed comparisons and frozen
   canonical goldens; no Debug-text oracle.
4. Materialize and independently review all sixty design vectors using actual
   production paths. Each future execution records decoded/reconstructed facts,
   reached stages, verdicts and precise identity relation. Do not copy Expected
   into Actual or count a fixture that never reaches its intended checker.
5. Carry portable P30 same-row containment and P31 resolver/recovery coupling
   into production tests. Do not treat stale process-local Root objects as an
   accepted portable input; the pipeline always derives them anew.
6. Demonstrate unknown/absence/duplicate/changed-pin/unsupported-content failure
   paths; malicious saved reports or checked flags cannot mint a capability.
7. Repeat frozen production regression, generator idempotence, registry coverage
   and independent soundness review. Report current-only or historical support
   only as actually implemented and qualified.
8. Keep rule-complete/cache/certificate/release features disabled until their
   own missing models and F03 obligations are closed.

No LockGraph, PlanCore, WorkflowVersion, Publication, DeploymentRevision,
Runtime/Journal/Reducer or trust-root service is authorized by these conditions.
