# Phase 4B.2A Proof Boundaries

## Claims this phase can make

- An exact ComponentContract digest resolves to a checked canonical body
  under the snapshot's exact proof-context object.
- Existing Phase 3C dataflow proves the call's expression availability,
  dominance, producer uniqueness, and lexical resource visibility.
- Explicit Component I/O/R port mappings satisfy the proof rules and exact
  public pins available in the current models.
- The scoped summary preserves source contract dimensions, per-call identity,
  resource coordinate translations, Flow provenance and proof references.
- A CALL_SUBFLOW target digest and Phase 3D derived interface resolve
  exactly; a complete separately supplied checked export may be compared.
- AWAIT's signal type pin and correlation use are structurally valid, while
  unsupported adapter dimensions remain explicit obligations.

## Claims this phase cannot make

- A checked declaration proves an external Component implementation.
- A target body has been inferred from its control tree or proves its export;
  absent complete trusted evidence this stays `RequiresEvidence`.
- Missing Failure/Effect/Flow/Usage/Recovery/Execution input means an empty
  row, zero cost, success, authorization, or idempotency evidence.
- Mapping a logical resource slot grants access or produces a handle.
- Static X requirements admit a worker or place a whole workflow.
- One leaf result composes into a workflow-wide contract. No control
  operators are implemented in 4B.2A.
- Any result creates a grant, lease, reservation, receipt, child run,
  attempt, plan, journal, reducer, or runtime state.
