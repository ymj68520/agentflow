## Entry to a separately authorized registration stage

The design is a sufficient basis for registration planning after all gate-report checks pass. The next task must explicitly authorize source/RuleId/version allocations and the complete migration transaction. Required approvals/implementation dependencies:

- An exact new semantics/obligation edition and normative source/RuleId allocation; no use of draft labels as official IDs.
- Portable current-profile specification/role/dependency changes consistent with the new source/rule set, not just a version-string edit.
- Current-only versioned migration and explicit legacy/new regression partition (or a deliberate reversal to separately specified historical support).
- Typed per-origin cause/evaluation/role/contradiction/prerequisite/reference facts, bounded identity normalization and independent validation, without changing verdict meanings or exposing constructors.
- G02 complete compiler/context/root-association projections, still **OPEN/P1**; a length, checksum, count or process pointer is insufficient.
- G03 independent nonempty Phase3D/Subflow interface Oracle, still **OPEN/P2**; no empty-interface substitute.
- New-version independent Expected, real mutations/hands, cross-process differential and adversarial audit. None of the declarative vectors is an executed production test.
