## Dependency proof

```text
actual declared inputs + actual native association
        → T3 preservation (not a complete Fact)
        → proposed structural input binding → immutable canonical G
        → actual C revalidation / Subject admission (outputs referencing G)
        → complete Raw Fact assembly from sealed real branch events (output)
        → T4 semantic consistency / obligations / canonical report (output)
```

No edge goes from a Fact/Obligation/report/C receipt back into G. The candidate
Subject data in G contains only compiler, Raw input/occurrence and source Context
with A snapshots/role partition, never its own admitted status or C output. C
has all native Context/source/compiler inputs without demanding a completed Fact.
Thus this schedule has a topological order and no T3→T4→T3 bootstrap cycle.
Existing graph mathematical laws remain in force; this schedule is a proposed
formal ownership grant, not an assertion of the current registered execution order.

The declared Raw profile has a fixed subject-root roster; all actual Context,
Snapshot A, package/binding/document nodes required by C/source/evidence must be
reachable from it. Do not add standalone report roots or arbitrary nodes to make
reachability pass. G is frozen before any source reference is emitted, so C and
later Fact construction cannot change canonical input ranks. The subject's
structural/admitted distinction requires the explicit successor amendment in the
stage contract; it is not an ad-hoc circular status input.

An output witness/value DAG W has its own minimal local roots/ranks. The future
registered field reference-domain table must say which edges are W-local and
which expressly target immutable G inputs. Local child height/order is computed
within W; declared external input references must resolve in G to exact target
types/values and its exact carrier. Rank numbers alone never identify the arena.
Facts and C outputs may be ordinary typed output records outside a value DAG;
their declared input references still resolve only in their envelope's G.
These domain bindings are part of the proposed amendment, not already supplied
by an arbitrary U64 or changed globally for all old profiles.
W's external-reference comparison resolves complete typed G targets rather than
ordering their rank spellings. Its complete envelope also retains and compares
the full G/tuple/profile/root environment, so comparing bare W payloads across
different input carriers is not valid complete-evidence equality.

Complete carrier contents, tuple and declared profile/root environment establish
which graph is meant. A checksum, allocation address, per-run UUID or arbitrary
global graph number is not the graph's semantic identity. Reuse requires complete
typed equality and the needed real native association checks, never digest-only
equality or equal encoded partition claims. A serializer's successful transport
is not a genuine branch/admission receipt and cannot forge a local seed.

## Five distinct identities

1. Content equality compares full typed values under exact nominal/site binding.
   Equal RawDocument values may intern, not create independent owners.
2. Occurrence remains O=(CompleteOwnerAnchor,actual document-entry ordinal).
   All namespace/domain/owner/revision UTF8 bytes, source package, selected full
   document and true internal declaration path remain source inputs. Different
   legal O values remain different even when they share a content node.
3. Context association is real analysis/canonical_validation same-object
   association. Equal contents, an asserted partition or equal G cannot prove it.
   Fresh binding under another actual object requires fresh association/admission.
4. C observation identity retains actual stage/source/current Context/compiler,
   exact slot/family/root and real lookup/validation results. A's native family,
   checksum, catalog/bytes and equality never turn into construction schema history.
   Equal A under changed current modules can produce different C observations;
   module definitions/context are retained completely. None executes no C check.
5. Fact identity inputs include full source/Scope/compiler/Context/predicate and
   real original/sorted member coordinates. Identical contents alone do not merge
   unrelated source facts. Only equal complete non-observation payload may union
   legitimate observations; conflicts reject, not verdict-max or last-write repair.

The old native snapshot constructor/equality and port algorithm are untouched.
Interning is not a source-event deduplication algorithm. Real port-event audit
IDs/case labels are not FactKey/Origin or invented source identity inputs.
