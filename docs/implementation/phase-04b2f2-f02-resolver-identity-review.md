# AUDIT-F02 — Resolver Identity and Root Provenance Review

## Identity structure and ownership

StaticComputationResolutionSnapshot::resolver_identity constructs a
process-local structural value from:

- sorted checked component-contract digests;
- for each sorted target SemanticIrDigest, its Option<Vec<direct dependency
  digests>>; and
- that same target row's Option<exported ComponentContractDigest>.

The target digest, dependency presence/value, and optional export digest live
in one ResolverSubflowIdentity record
(crates/af-computation/src/resolution.rs:107-132,188-212). None remains
distinct from Some([]). Sorting is deterministic by exact digest tuple, and
does not discard the target-to-export association.

The identity is generated by the immutable snapshot, not accepted from the
caller. Fields are private, and no digest/serialization/wire identity is
claimed. Snapshot component/export contracts are checked under the snapshot's
proof context by the builder; direct dependencies come from the validated
SubflowIrUniverse target IR.

The checked caller SemanticIrDigest is a separate exact pin: RootExport
recomputes it and requires it to match both the assertion and the source digest
stored in Root (root_export.rs:918-937). The assertion's subflow dependency
closure is independently compared with the current snapshot (974-978).

## Root and RootRecovery binding

DerivedWorkflowContractSummary has private fields for root, closure,
root_recovery, and resolver_identity; callers can read but cannot construct
it (crates/af-computation/src/control.rs:321-345). The sole public derivation
entry point checks exact proof-context identity, resolves leaves against that
snapshot, derives the control root, checks closed-world effect/residual/
recovery-source accounting, derives RootRecovery from that same root, and
stores snapshot.resolver_identity() in the same returned summary
(control.rs:1204-1329).

RootRecoverySummary fields are pub(crate) and have no public constructor
(crates/af-computation/src/root_recovery.rs:174-212). Repository search found
no deserializer or alternate public assembly path. A caller cannot pair
Root(A) with separately supplied RootRecovery(B). Within the crate, the
audited construction path is the single root derivation described above.

The exact StaticContractProofContext pointer is separately checked for the
checked export, current snapshot, and root derivation. Structural resolver
equality is an additional condition, not a substitute for context equality.
The assertion's content-complete manifest and exact source/export pins remain
independent preconditions.

## Same digest set, different association

An independent checked two-target fixture held the set of exported contract
digests constant while swapping target associations:

| Target | Root(A) export | Current Snapshot(B) export |
| --- | --- | --- |
| db653ab… | 40d980… | 8ef338… |
| ddc11e… | 8ef338… | 40d980… |

The unordered export digest sets were equal. Structural identity comparison
still failed at proof-context; exact context, assertion inputs, compiler
semantics, and subflow dependency preflights were otherwise proven. All nine
dimensions were withheld as Unproven; overall was Unproven; no checked
capability was issued. Thus the identity preserves the association and is not
merely a sorted set of digests.

The checker-side typed target mapping additionally binds each call-site target
IR digest. A duplicate target with two exports is rejected by the snapshot
builder before RootExport (duplicate exported contract for SemanticIrDigest);
it is reported as an earlier validation rejection, not as a checker pass.

## Equality versus object identity

The audit distinguishes:

- **same context pointer**: required by the established context boundary;
- **same resolver object**: not required;
- **same resolver content**: structural identity equality is sufficient; and
- **same semantic associations**: each target/dependency/export tuple must be
  equal, including absence versus presence.

Two independently built snapshots with exact same checked content and
associations retained proof-context=Proven. Reverse insertion order with the
same association also retained the identity preflight, confirming ordering is
canonicalized. The saved reverse-order probe log did not retain its overall
compatibility verdict or capability bit, so it is not used as a positive
compatibility result.

## P31 reproduction

The independently reconstructed P31 uses Root from Snapshot A with target
export digest
2019eeb505c3d1e14fa086a89bd3868a6f1692224fbad44f3651fe493943afc5,
current/assertion Snapshot B with target export digest
1851278a5faa9a8b239abe89d4191d3f3735b83004124894b791304ba07fc661, and an
unchanged top export with effect upper 1. The exact equality check fails before
the nine dimensions. Actual: proof-context Unproven, all nine dimensions
Unproven, overall Unproven, no checked capability. Body conformance remains
RequiresEvidence.

Separate fresh-root-under-B and exact-content separate-snapshot probes show
the intended asymmetry: a fresh root is checked against current content and
can produce a real Violation when the top export is too narrow; equal
snapshot content remains eligible for proof. A changed snapshot is not
accepted merely because the top export is unchanged or wider.

## Conclusion

Every resolver-derived source used by Root and RootRecovery is bound through
the same checked snapshot identity, while caller IR, context, dependency
closure, and top export are checked independently. Snapshot mismatch fails
closed before any dimension is proved. AUDIT-F02 is CLOSED.
