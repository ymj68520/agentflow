# Portable Proof Inputs — v1

Status: normative. Schema family agentflow.portable.proof.inputs@1 is defined
by spec/idl/portable-proof-inputs.afidl. This specification registers the
Phase 4C.1A static input model. It does not alter ACE1, AFIDL1, HashV1, Semantic
IR, ComponentContract, or existing checker semantics.

## Registered shape and ownership

<a id="ppi-closed-schema"></a>

AF-SEMANTIC-0173: The Bundle MUST have exactly the ten numbered fields in
PortableProofInputBundle. All fields, including options, are required.
Unknown fields/cases/enums and missing or duplicate fields MUST fail closed.
Records, variants, enums, aliases and imports have their complete registered
AFIDL meanings. There is no extension map or caller-established checked flag.

The Bundle owns schema/IR/contract assets, finite structural witnesses, context,
resolver, compiler and assertion tables. An AssertionEntry binds its exact
IR/export assets to its asserted pins and scoped context/resolver/compiler.
Every record owns its fields. All lists are finite. Option has zero/one
payload, represented by explicit none/some; every other field has exactly one
value. Bytes are inline, not locators. IDs are positive uint32 and Bundle-local,
with separate Context/Resolver/Compiler/Assertion/StructuralType namespaces.
Ordinal64 is a zero-based uint64 witness, not a local ID or host-size integer.

The seventeen PpiAux declarations are distinct anonymous-shape occurrences.
Names are PpiAux + owning type + P + traversal path. F/C identify positive
field/case numbers, L1/M1/O1 structural wrappers and G1 generic instantiation.
The published full inventory is fixed by AFIDL, not regenerated by a host's
generic/HashMap/reflection order. Equal shapes at distinct paths stay distinct.
No alias is introduced for an existing imported TypeSchemaRef/DigestRefValue;
IrPin/ContractPin/SchemaPin are refinements of that imported value shape.

## ACE1 and stages D0–D1

<a id="ppi-exact-scalars"></a>

AF-SEMANTIC-0174: Scalars MUST use unchanged ACE1 types and widths; machine
numbers are strings, Int64/uint64 never pass through floating point, decimal
is exact, bytes are unpadded base64url, Unicode is valid UTF-8/NFC, and all
PrimitiveConstant alternatives retain their imported nominal meanings.

<a id="ppi-presence"></a>

AF-SEMANTIC-0175: Missing, None, Some(empty), Some(nonempty), Complete(empty)
and Unavailable MUST remain distinct. Unavailable and missing catalog data
MUST NOT be replaced by a default empty collection. None dependencies may
pass D0–D4 as a faithfully retained raw claim; complete reconstruction is a
later operation and cannot succeed on that basis alone.

<a id="ppi-canonical-bytes"></a>

AF-SEMANTIC-0176: D1 MUST require exact equality between received bytes and
schema-directed canonical re-encoding. Noncanonical object order, whitespace,
escapes, numeric strings, Unicode and bytes MUST NOT be repaired into success.
Ordered sequences MUST retain order. An author-side encoder may sort declared
sets but MUST reject duplicates and noncanonical identity text.

<a id="ppi-set-order"></a>

AF-SEMANTIC-0177: Every set below MUST be ordered by its typed primary key,
then full canonical element bytes. Identical duplicates fail D1. Distinct
rows with the same unique identity fail D2. Numeric ordering is mathematical,
text ordering unsigned UTF-8, option ordering None before Some, and tuple/list
comparison lexicographic. Enum/variant ranks use existing assigned numbers.

DigestKey=(algorithm,domain,hex); SchemaKey=(specification_id,type_name,DigestKey);
ContentKey=(DigestKey,SchemaKey). RefKey=(catalog,name).
AtomKey=(operation RefKey, selector port, sorted scope(key,value), complete
qualifier identities by family/member number and payload).
ActionKey=(forward AtomKey, action kind rank, action AtomKey).

| Collection / element | Primary key | Unique identity |
| --- | --- | --- |
| schema_assets | reference SchemaKey | full reference |
| ir_assets / contract_assets | reference ContentKey | full reference |
| Bundle ID tables | numeric id | id within its table |
| context modules / EffectCatalogContent / normative sources | specification_id | specification_id |
| schema membership / resource descriptors | SchemaKey | logical specification_id,type_name within that scope |
| ModuleContent.named_types | local type_name | local type_name, matching owning module |
| labels / taints / reconciliation / trust / regions | RefKey | RefKey, independently per collection |
| FlowEffectSinkContent | operation RefKey | operation |
| UsageMeterContent | meter RefKey | meter |
| ExecutionCapabilityContent | capability RefKey | capability |
| ExecutionRuntimeProfileContent | profile RefKey | profile |
| RegionCompatibility | from RefKey,to RefKey | same pair; direction retained |
| text/numeric/attribute member sets | value or (key,value) | same full value |
| semantic_roles / depends_on | assigned SemanticRole rank | role |
| rule sets / dependency edges | rule_id / (dependent,prerequisite) | same key |
| resolver components | ContentKey | exact contract digest within resolver |
| ResolverTarget / SubflowTargetIdentity | target DigestKey | target digest |
| SourceAssociation | caller digest,source_node | same scoped pair |
| input mappings | export port,run parameter,value slot | exported input identity |
| input use sites | computation,source digest,source port,expression | same tuple |
| output mappings | export port,output name,expression | exported output identity |
| resource mappings | export port,root slot | exported resource identity |
| resource sources | source node,digest,source port,slot | same tuple |
| effect mappings | export AtomKey,caller digest,node,source digest,ordinal | full source occurrence |
| recovery mappings | export ActionKey,caller digest,node,source digest,ordinal | full source action |
| execution mappings | source node,source digest | same pair |
| subflow mappings | target digest,call_site | caller-local call_site |
| flow mappings | FlowMappingKey below | source node,source digest,flow ordinal |

Every CompleteCollection.complete payload uses the element order above.
DependencySlots, alias ports and leaf-local Flow occurrence-index sets sort
numerically. FlowMappingKey=(class, optional export constraint, optional export
source, source digest,node,ordinal); class is 0 for Some export_sink, 1 for only
Some export_source, otherwise 2. ConstraintKey=(FlowKind rank,SinkKey).
SinkKey=(workflow_output rank 1,port) or (external_effect rank 2,RefKey).
SourceKey=(workflow_input rank 1,port), (resource_requirement rank 2,port), or
(unknown_external rank 3). FlowKind ranks data_egress=1/decision_influence=2;
recovery kind reconciliation=1/compensation=2.

Imported inline list fields retain their existing semantic set ordering:
scope bindings and capability attributes by (key,value); qualifier identities
by full assigned family/member; allowed_effects by AtomKey; Usage limits by
(phase rank,meter RefKey); capability requirements by (RefKey,exact_version);
compute quantities and preferences by assigned rank; ABI requirements by
SchemaKey; region lists by RefKey; required features by UTF-8. Raw IR/contract
asset blobs receive D3 shape/canonical-byte checks, not D6/D7 semantic ordering,
normalization, dataflow or contract consistency proofs.

## References and finite graphs

<a id="ppi-scoped-ids"></a>

AF-SEMANTIC-0178: D2 MUST resolve each local ID in its declared namespace,
reject zero and duplicate identities, and preserve local ID assignments.
Equal expanded types with different IDs may have different evidence bytes.
Integers from different port/slot/caller namespaces imply no correspondence.

<a id="ppi-assets-inline"></a>

AF-SEMANTIC-0179: All required typed assets MUST exist inline under the full
typed key. No URL, filesystem, network, environment or latest lookup supplies
missing data. An IR content ref MUST use semantic-ir and the exact registered
SemanticIrDocument root; a contract ref component-contract and ComponentContract.
Every nominal SchemaRef includes a valid type-schema pin.

<a id="ppi-reference-closure"></a>

AF-SEMANTIC-0180: Root, context, resolver, compiler and assertion asset pins
MUST agree through their exact declared references. D2 MUST reject conflicting
asset rows, dangling references and unowned transport padding. Reachability
includes explicit complete context/resolver inventories and compiler schema
requirements; unused inventoried members MUST NOT be pruned.

<a id="ppi-finite-graphs"></a>

AF-SEMANTIC-0181: StructuralType and assertion-target graphs MUST be finite,
reference-closed and acyclic, using bounded iterative traversal. Structural
references expand only within the structural table; schema witnesses retain
their exact nominal pins. Fresh witness agreement with derived workflow
types is reserved for D7–D10 and MUST NOT be reported by D2.

<a id="ppi-associations"></a>

AF-SEMANTIC-0182: Resolver rows MUST preserve caller/node, target/export and
direct/transitive optional association facts; duplicate/conflicting keys
fail. Some references resolve to declared inventory; target/content pins and
source call_subflow association pairs agree. D2 checks declared references.
Actual IR source kind/edge derivation, closure equality and unsupported
resolver-cycle analysis remain D8; no resolver snapshot is created here.

<a id="ppi-context-scopes"></a>

AF-SEMANTIC-0183: Context member scopes MUST be kept independently, including
global schemas versus resource schemas and context effects versus recovery
effects. D2 validates member uniqueness and exact referenced assets. Constructor
semantics, recognized-resource compatibility, available relation evidence and
execution feasibility are later checks. D0–D4 MUST NOT merge these scopes.

## Content validation D3

<a id="ppi-schema-content"></a>

AF-SEMANTIC-0184: SchemaAsset bytes MUST decode the existing closed canonical
TypeSchema grammar, with exact schema/name, legal identifiers/numbers, sorted
unique fields/cases/values and canonical re-encoding. HashV1(type-schema,bytes)
MUST equal the pin. CanonicalTypeExpr has primitive/ref/list/map_string/option;
references keep full logical names. It is a bounded blob grammar, not a new
recursive AFIDL declaration. Context-specific named-ref resolution remains D5.

<a id="ppi-ir-contract-content"></a>

AF-SEMANTIC-0185: IR/contract assets MUST match their existing HashV1 domains,
known exact nominal root schemas and schema-directed canonical byte roundtrip.
D3 MUST NOT issue CheckedIrDocument or CheckedComponentContract, nor interpret
generic ACE1 validity as semantic canonicalization/validation.

<a id="ppi-checksum"></a>

AF-SEMANTIC-0186: Normative source, registry, closed table and relation content
checksums MUST use plain SHA-256 over exact bytes. HashV1 and file checksums
MUST NOT substitute for one another. Relation bytes MUST have the exact imported
root shape/pin and canonical form; rebuilding RelationCatalogSnapshot is D5.

<a id="ppi-source-registry"></a>

AF-SEMANTIC-0187: A compiler manifest MUST inline both registries, all four
closed tables and every Specifications Registry source row, with exact
path/checksum/content association. Registry parsing rejects duplicate keys
and unknown members. Declared source membership, rule rows and role references
must be internally consistent. No omitted source is supplied by local lookup.

## Supported profile D4

<a id="ppi-current-profile"></a>

AF-SEMANTIC-0188: D4 MUST compare the entire CompilerSemanticsManifest with
the implementation-owned current exact profile, including all bytes, checksum
fields, roles, dependencies, schema requirements, version and rule metadata.
Caller-submitted support declarations have no authority.

The current version token is agentflow.root-export-checker@1. Its exact sixteen
static normative IDs are the ones bound by the existing current checker; its
84 applied rows remain AF-CONTRACT-0001..0022 and AF-SEMANTIC-0111..0172.
Each of eight defined static roles binds those sixteen IDs and all named
schemas compiled from current registered AFIDL sources. Dependencies are:
contract/IR validation none; dataflow→IR; leaf→contract/IR/dataflow;
control→leaf; recovery→control/dataflow; root_export→all six prior validation/
derivation roles; static_analysis→all seven other static roles.
The post-registration full registry/source/table tuple is a new identity even
though existing checker semantics and its static version token are unchanged.

<a id="ppi-role-boundary"></a>

AF-SEMANTIC-0189: Exactly ten role entries MUST be retained. Eight static
roles have definitions; plan_lowering and runtime_semantics_profile MUST be
model_missing:not_formalized in the initial supported profile. Recognizing an
implemented static algorithm MUST NOT assert that it ran on this Bundle.

<a id="ppi-attribution"></a>

AF-SEMANTIC-0190: Only full_content_revalidation (Profile A) is supported.
Its listed_rules equals the static projection's applied_rules. Profiles B/C
MUST fail D4 UnsupportedAttributionProfile. F03 stays OPEN/P2; 84 rules are
not a complete rule dependency closure or a proof certificate.

<a id="ppi-no-upcast"></a>

AF-SEMANTIC-0191: Unknown, conflicting and historical semantic content MUST
fail D4 UnsupportedSemantics in this implementation. No implicit upcast,
label substitution, latest selection or historical dispatcher exists.

<a id="ppi-no-capability"></a>

AF-SEMANTIC-0192: Stage wrappers MUST have private construction through their
validators and immutable access. SupportedPortableStaticInputs means D0–D4
only. It MUST NOT imply checked contracts/IR, reconstructed context/resolver,
RootRecovery, RootExport Proven, origin authentication or publication rights.
Submitted reports/flags cannot mint those capabilities. B01/B02 implementation
closure and B03–B07 remain blocking; F04 is unchanged OPEN/P2.

## Limits, determinism and conformance

<a id="ppi-resource-limits"></a>

AF-SEMANTIC-0193: Each production entry MUST enforce explicit byte, nesting,
scalar, container, total-node and graph-work bounds before unbounded allocation
or traversal. Native index conversion is checked. ResourceLimit is an
infrastructure failure, never partial success, semantic Violation, empty
replacement, truncation or an unlimited fallback.

The implementation may enforce stricter local bounds. Roundtrip/determinism
laws apply to complete inputs within the shared declared limits. Deep raw
schema expressions and assertion/structural DAGs must fail safely. Comparisons
must not expand a shared DAG exponentially.

<a id="ppi-independent-conformance"></a>

AF-SEMANTIC-0194: Production results MUST be compared with independently
authored Python canonical bytes, stage/errors and typed projection expectations.
The oracle MUST NOT invoke Rust, consume Actual output or repair negative
inputs. Formal schema data may be shared; Expected-producing business logic
may not. Every declared case must execute and compare all required fields.

<a id="ppi-additive-freeze"></a>

AF-SEMANTIC-0195: All pre-existing AFIDL definitions, 477 ABI rows, normative
rule rows, specification rows, domain meanings, digest goldens and historical
RootExport Expected MUST remain unchanged. New schema/rule/ABI/conformance
rows are additive. No PortableBundleDigest or RootExportAssertionDigest exists.

<a id="ppi-mutation-evidence"></a>

AF-SEMANTIC-0196: Comparator mutations and actual malformed production-input
mutations MUST be recorded as separate evidence. Manifest, executed and fully
compared counts must agree, with zero skipped, unexpected mismatch, uncovered
required fields, truncation or incorrect positive acceptance.

Conformance: spec/conformance/portable-proof-codec/ and its independent generator
tools/gen-portable-proof-codec-corpus.py. Rule coverage is registered through
SUITE-PORTABLE-PROOF-CODEC, whose production tests exercise D0–D4, typed scalar
and complete Bundle roundtrips, errors, finite graphs and additive snapshots.
