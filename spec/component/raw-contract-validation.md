# agentflow.component.raw-validation.semantics@1

Registered non-wire staging, NOT implemented typed Capture, full Scope, normalizer
or positive capability. Exactly one family raw_contract_validation and one case
positive_unique_io_ports. Native seven cases and Standalone twenty-seven cases
retain their frozen semantics. The concrete model@4 resolves all logical types.

## Subject and real source

RawValidationSubject has owner_compiler CompleteCompiler, input RawParsedInput and
context RawContextBinding. The complete thirteen-field RawCandidateContract is a
parsed declaration, not CanonicalComponentContract, Checked, or arbitrary JSON.
RawDocument is physical_json_utf8(bytes) or declared_native_document(declarations).
RawInputOrigin has full document and exact entry path. RawPhysicalAssociation is
not_supplied or supplied(document,value_path). NotSupplied is not known empty.
Native APIs require a real supplied declarative document and entry; adapters MUST
NOT create a default one-entry document from a call, ProbeId, clock or source line.
MissingDeclarativeOrigin rejects admission and yields no portable originating fact.

The physical source is complete original bytes, never reserialization, display,
canonical bytes or a digest. Different physical bytes remain different source
identity even when parsed values agree. RawUtf8Bytes validates UTF-8 without NFC
repair. Duplicate JSON keys, malformed UTF-8/JSON/structure, unknown/missing fields
and wrong numeric widths reject before RawParsedInput, not as this port Violation.
The physical document uses the schema-directed closed RawCandidateContract JSON
metadata representation: explicit byte arrays, exact named fields, tagged options
and variants. It is non-wire G01 source content, not a new AFIDL transport. A
native typed document uses complete actual ComponentContract values; no shape
probe proves historical provenance, validator execution or a trusted fact.

## Context and stages

ContractProofContextContents retains the exact nine fields and three named optional
relation snapshots. The two roles analysis/canonical_validation are the actual
same borrowed context object; partition is [[analysis,canonical_validation]]. Equal
contents of distinct objects do not prove aliasing. No resolver_dependencies is
added. Old resolver-bearing subjects keep all strict requirements. Portable full
content/partition projection remains Pending G02; native addresses are not encoded.

Raw physical input, parsed Raw declaration, canonical diagnostic presentation,
canonical validated declaration and Checked are five distinct states. No early
rejection has a successful canonical declaration, ACE1 encoding identity or Checked
digest. Display may be NFC but cannot replace NFD physical/raw history or repair
an invalid field. Canonical/Checked positive source requires its own real stage.

## One exact predicate and actual prefix

Kind prerequisite; role supporting_fact; stage contract_validation; closed substage
canonical_validation/io_port_check; EvidenceClass static_declaration; Requirement
raw_validation:positive_unique_io_ports; Dimension supporting(exact PredicateId).
Substantive governing rule AF-CONTRACT-0004, component-contract-ports. This is not
whole schema validity and does not redefine the wider exact type-pin rule.

Actual order is component identity, input namespace, output namespace. For each
namespace stable sort mathematical U32 port number, retaining original ordinal.
At each reached port evaluate number>0 && number!=previous_number before schema
resolve. Initial previous_number=0 has NO actual predecessor. Fresh positive=P,
zero=V, duplicate positive=V. No U/RequiresEvidence is invented for this local
condition. Earlier component identity rejection yields no port events; schema
resolution after a positive port can stop later events. Reached, not_reached,
stopped_by_earlier_failure and no_port have explicit typed applicability, not
evaluated U placeholders. Same input/output number is not a namespace duplicate.
One local P proves neither all ports nor schema nor whole contract. Invalid
identity, schema query, Guard, Recovery or encoding errors are UnsupportedPredicate
for this family, never a generic schema-invalid catch-all. Capture errors do not
rewrite formal Checker Verdicts.

## Location, references and evidence

Source.raw_validation binds full subject. Target.raw_declaration_constraint binds
the exact complete compiled ComponentContract schema reference, full rule-content
reference, direction and exact constraint. A schema reference is input association,
not a claim that the port validator ran a new shape query. Coordinate.raw_port has
direction, original ordinal, sorted ordinal, U32 port number and member=port_no.
Invalid zero is not stored under a positive-only nominal PortNo.

RawValidationOrigin retains actual document/path/direction/original ordinal.
Successor Origin.raw_validation_origin is Some exactly for this family and None
for all unaffected families. Existing declared_path is real DeclaredStep fields /
entries rooted at subject.input.candidate; its final port member and RawDocumentMember
path MUST resolve to the same original occurrence. These path types are not cast.
Same originating fact copies union only legitimate observations; conflicting
same-origin values reject. Independent declared entries remain distinct even with
equal errors or equal raw bodies. No call count, report index, synthetic node or
root is an Origin.

RawPortCheckBasis retains subject, full occurrence, optional actual predecessor,
condition, selected typed error and exact rule. Zero witness has U32(0),minimum1,
full occurrence and no fictional real predecessor. Duplicate witness has both
distinct original ordinals and equal positive numbers in one namespace, with the
actual earlier sorted predecessor. Positive P has no witness; V requires exactly
its matching zero/duplicate witness. No Guard assignments, resolver query result,
Root countermodel, receipt or Checked token is permitted. Legacy ContractError
detail is retained only as diagnostic output, not parsed into the condition/witness.

Fact.raw_validation_basis is Some only in this family, with old optional bases
None. TypedContradiction.raw_validation contains its closed witness. EvidenceRef.
raw_validation_member names the actual input member; RuleRef is not EvidenceRef.
Duplicate adds both original member refs. Derive all required references and typed
minimum primary. ObservationOwner.raw_contract_validation does not change native
or Root origin. Prerequisites retain exact original stage/source/support/consumers;
there is no schema-resolution premise before zero. A later namespace premise
requires complete actual coverage and real source/context, not one positive port.

## Future hook contract only

Typed evidence MUST be created at canonical_ports before reduction to strings;
the outer analyze_contract hook before invalid_contract_report can only associate
already produced evidence with borrowed raw/context/declarative source. Input,
context and evidence lifetimes bound all local views. Admission requires complete
compiler, structural parse/native association, real Origin, same actual context
and genuine branch evidence. Metadata APIs return unit, never validator facts,
trusted Proven, Checked, CompleteView or normalized identity. No hook is implemented
by registration. Missing source/evidence fails explicitly, not an empty success.
