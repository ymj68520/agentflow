## Candidate data is not an admitted Subject

The RawValidationSubject descriptor under the successor model denotes complete
candidate **input data** (Compiler, actual Raw input/occurrence and Context with
native A). It may be bound in G before C. This explicitly changes the old OS@6
wording that prevented full Subject materialization without C Valid: that old
wording and old model@6 are not retrospectively reinterpreted.

An admitted Subject usable for Source.raw_validation, Target.raw_validation,
RawPortCheckBasis, RawPortRejectionWitness, Origin and EvidenceRef additionally
requires genuine source/native association and actual C admission for every Some.
StructuralSubjectAdmission is an output claim linked to the exact G Subject;
only genuine future checked admission, not its shape/boolean/assurance spelling,
can satisfy consumer admission. C observes actual current modules/Context under
the same genuine native association. Found is not Valid. Each Some requires all
registered C steps Valid; None executes no snapshot/schema validation. Native A
family/pin/bytes/catalog/equality and all AF-SEMANTIC-0286..0298 meanings remain.

C Missing/Invalid preserves A, source, actual port event/verdict and typed failure.
It emits no complete Raw Fact and no fourteen fabricated roots. Candidate data
is not predicate evidence or a checked capability. C output/receipt is not a
descendant of G or part of input identity. No construction-time schema history
is recovered from current validation or equal native snapshots.

## Root and consumer propagation

The successor ScopeSubject.raw_contract_validation is explicitly
`{subject:Node<RawValidationSubject>}`. Its declared ordered root roster has that
one Subject; all required source/package/document/Compiler/Context inputs are
reachable from it. The old inline raw branch in model@6 remains frozen. Ordinary
U64 fields are data, not input references. ModelType registration ranks and source
ordinals cannot substitute for DagRank.

All affected Source/Target/Coordinate/Origin/Basis/Witness/Evidence/C fields retain
their exact nominal target descriptor and registered reference environment. Plain
Fact/observation records remain outside input G. Supported witness values may use
W, whose local/input edges are explicit; all input references resolve in the exact
enclosing G. The domain table also inventories other profiles, which remain
NotImplemented rather than silently gaining Raw binding support.

Full source occurrence O is complete OwnerAnchor plus actual entry ordinal.
Equal complete document content can intern without merging different legal O.
Source/Origin/member paths, package/revision and original/sorted coordinates are
retained; observation does not create origin. Native object addresses, per-run
IDs and caller booleans never become source identity. Only equal complete facts
may merge legitimate observations under the existing rules.

The dependency order is complete declared inputs -> immutable G -> actual C /
admission -> genuine local Fact assembly -> future T4 normalization. No Fact,
Scope result, obligation or report determines G's type, child, identity or rank.
T4 cannot fill a missing input reference or re-rank G. G02 complete Scope/transport,
Native Full Seed, Standalone and other producers remain independently incomplete.

The retained previous-model ledger is177 real port events,176 otherwise full-Fact
applicable executions,2,464 required root comparisons and0 full-field comparisons.
Nested/Relation runtime denominators stay UNKNOWN. New registration does not
reduce those gaps or fill three old verdict-only coordinate records. A future
producer must independently recalculate its exact new full denominator.
